# ALP Plants 2.0.0 — Gemini Collection

High-resolution plant library built from Gemini PNG artwork (line + watercolor pairs).

**Current release:** v2.1.0 — **63 catalog entries** sharing **33 artwork stems**.

---

## Quick rebuild

From repo root, with source PNGs in the default folder (`~/Downloads/ALP Plant Library Images/Trans PNG`):

```bash
./scripts/build-alp-plants-gemini-library.sh
```

Custom source folder:

```bash
./scripts/build-alp-plants-gemini-library.sh "/path/to/Trans PNG"
```

Output: `ALP-Plants-2.0.0.sh3f`

The build script runs the full pipeline in order:

1. Regenerate `plants.catalog.json` from `scripts/generate-plants-catalog-json.py`
2. Split side-by-side pairs **01–25** (fixed stem order — see below)
3. Add Plant 14 matched pairs **26–30**
4. Add Plant 15 matched pairs **31–33**
5. Write `PluginFurnitureCatalog.properties` from catalog JSON
6. Zip into `.sh3f`

Intermediate assets land in `build/` (`icons/`, `plan-icons/`, `plan-icons-line/`, `staging/`).

## Key config files

| File | Role |
|------|------|
| `plants.catalog.json` | **Source of truth** for display names, stable IDs, and footprints (cm). Generated by `scripts/generate-plants-catalog-json.py`. |
| `gemini-stem-order.json` | Fixed mapping of `plant-01` … `plant-25` → side-by-side source filenames. Edit if stem order must change. |
| `build/gemini-manifest.json` | Build output: source file → stem, pixel sizes, gutter/split metadata. Regenerated each build. |

### Variant model

- One **stem** (`plant-NN`) = one shared PNG set (same icon, plan line, plan fill).
- One **catalog entry** = one row in the furniture library (name + width/depth/height).
- Multiple catalog entries can reference the same stem (e.g. `plant-01` → Magnolia + Awabuki Viburnum).

### Dimension rules (when editing catalog)

- User sizes are **height × width** in feet (or inches for small groundcover).
- Catalog fields: `heightCm`, `widthCm`, `depthCm` where **width = depth** (round plan footprint).
- Display names are **species only** — size is implied by footprint, not shown in the name.

To change a name or footprint, edit `scripts/generate-plants-catalog-json.py` (`VARIANTS` list), then rebuild. Bump `libraryVersion` in that script when releasing.

Duplicate species on different stems (e.g. Podocarpus on plant-07 and plant-17) get **unique IDs** (`alp-plt-podocarpus`, `alp-plt-podocarpus-p17`).

3. Drag **new** pieces from **ALP Plants** (re-drag after rebuild; placed pieces keep old catalog data)

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Wrong stem numbering after rebuild | Ensure `gemini-stem-order.json` is used (`--order-file`); do not rely on glob sort alone. |
| Plant 14/15 missing | Confirm pre-split PNGs exist in source folder; check build log for "Added N plants". |
| Draft and Presentation look identical | Properties need escaped `planIconLine#N\:CONTENT` — see `alp-phase-1-library-schema.md`. |
| Library in About but no pieces | Properties must be ISO-8859-1 / ASCII. |

Schema details: `alp-phase-1-library-schema.md` and `Building ALP CAD  Libraries.md`.
